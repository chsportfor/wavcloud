# WavCloud 웹사이트 적용 결과

2026-10-07 한국 시간. 운영 주소: https://wavcloud.duckdns.org.
웹 버전: `772e26ff899ff4c8`.

## 적용한 기능

기존 운영 웹의 별도 압축 번들을 Android에서 정리한 공통 화면·재생·목록 코드로 교체했다.
`android-app/tools/web-source.mjs`가 두 빌드의 모듈 순서를 관리하고,
`web-app/`에 웹 전용 템플릿·PC CSS·키보드 조작·PWA·빌드·검사·배포 도구를 추가했다.
앞으로 공통 기능 수정은 같은 소스에 반영한 뒤 웹과 APK를 각각 빌드한다.

- 900px 이상의 PC 화면: 왼쪽 메뉴, 검색, 여러 열의 앨범 목록, 하단 플레이어와 음량 조절.
- PC 전체 플레이어: 큰 커버 옆에 현재 곡과 다음 재생 대기열을 함께 표시.
- 작은 창과 모바일 웹: 모바일 배치와 플레이어·대기열 전환 유지.
- Ctrl+K, Space, 좌우 탐색, N/P, M 단축키와 재생 위치 슬라이더의 키보드 탐색.
- 앱과 같은 목록 재시도, 다운로드 공유·오류 복구, 스캔 진행, 폴더 입력과 업로드.
- 앨범 상세의 검색 누락, 손상된 음량 값으로 초기화가 중단되는 문제,
  탐색 슬라이더에 포커스하면 플레이어 상단이 밀리는 문제 수정.
- 파일 찾기를 키보드로 사용할 수 있는 버튼으로 변경하고 로그인 화면의 이름·필드 표시 정리.
- 재생목록 공유·서버 동기화와 인증·계정 정책 변경은 포함하지 않았다.

## 캐시와 데이터 보존

CSS·JS 이름은 내용 해시를 사용하고 HTML·서비스워커는 갱신을 확인한다.
기존 `cm_*` 로컬 저장 키, 음원 `audio-cache`, 앨범아트 캐시를 유지한다.
옛 Workbox 화면 캐시만 교체하며 로그인·업로드·라이브러리 API를 서비스워커에서 캐시하지 않는다.
오프라인 음원의 전체·부분·suffix·HEAD 응답과 잘못된 범위의 416 응답을 처리한다.
업데이트가 준비돼도 재생 중 화면을 강제로 새로고침하지 않는다.
실행 중인 JS·CSS와 새 서비스워커의 자산을 비교하므로 이미 최신 화면이면 갱신 안내를 띄우지 않는다.
CSS만 바뀐 버전도 새 버전 안내를 표시한다.

실제 UI 검증은 Codex 내장 Chromium 브라우저로 수행했다.
Firefox·Safari, 실제 휴대폰의 백그라운드 재생과 홈 화면 설치는 이번 작업에서 실행하지 않았다.
이번 수정은 웹에 적용됐으며, 공통 소스 수정이 기존 설치 APK를 자동으로 바꾸지는 않는다.
Android 재생 브리지는 변경하지 않았다. 새 APK 제작은 별도 빌드가 필요하다.

## 운영 백업과 복구

웹 변경 전 전체 배포물과 Nginx 설정:
`/opt/cloudmusic/backups/web-refactor-20261007T084916Z-HkAi`.

최종 업데이트 안내 수정 전 백업:
`/opt/cloudmusic/backups/web-refactor-20261007T100346Z-gig6`.

원래 웹으로 되돌리려면 첫 백업의 `dist/.`와 `nginx.conf`를 복원한다.
최종 직전 상태로 되돌리려면 두 번째 백업을 사용한다.
절차는 [웹 개발·배포 안내](../web-app/README.md)에 있다.
API 서버·음원·계정 파일은 이 웹 배포의 교체 대상에 들어가지 않았다.
